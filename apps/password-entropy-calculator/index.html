How password entropy is calculated

            
If a password has L characters chosen at random from N possible ones, there are NL combinations and its entropy is L × log₂(N) bits. For example, 12 characters with lowercase, uppercase, numbers and 32 symbols (N = 94) give about 79 bits.

            
The average time to find it by brute force is half the combinations divided by the attacker’s speed. Change the speed, from an ordinary CPU to a server farm, to see how it affects the result.

            
Character set sizes

            
  • Lowercase only: 26 characters.
  • Lowercase and uppercase: 52.
  • Letters and numbers: 62.
  • Letters, numbers and ASCII symbols: 94.

            
frequently asked questions

            

                
Which is safer, a longer password or one with more symbols?+
A longer one. Going from 62 to 94 possible characters adds about 0.6 bits per character; adding one more character adds about 6 bits.

                
How many bits of entropy are enough?+
Below 36 bits is weak; from 60 bits it is considered strong, and 128 bits is out of reach of any brute-force attack.

                
Does it work for a password I made up myself?+
Only as an upper limit, because the formula assumes random characters. For a specific password use the strength checker, which also spots weak patterns.
