How it works

  • With the same details and options you always get the same password, on any device. There is no need to store it anywhere.
  • The master key goes through PBKDF2-SHA256 with 600,000 iterations: every attempt to guess it is very expensive, even if someone obtains one of the generated passwords.
  • If you change any detail or option (length, character types, username, version), the password changes. You can write down the options for each site: they are not secret.
  • The site is normalised: https://www.GitHub.com/login i github.com give the same result.
  • If you forget the master key, there is no way to recover the passwords. Choose a long one that is easy to remember.

Deterministic passwords: one master key for everything

PassForge doesn’t store your passwords: it calculates them every time from your master key, the site name, the username and the version. The same details always give the same password, on any device, with nothing to sync and no server involved.

The derivation uses PBKDF2-SHA256 with 600,000 iterations, the value recommended by OWASP, so every attempt to guess the master key is expensive even if someone gets hold of one of the generated passwords.

Pros and cons

  • Pro: there is no vault to steal and it works offline.
  • Con: if you forget the master key, there is no way to recover the passwords.
  • Con: if you change the master key, every password changes.

frequently asked questions

How is it different from a password manager?+

A password manager keeps an encrypted vault of your passwords; PassForge stores nothing and regenerates them when you need them. In exchange, it can’t keep passwords you already had.

What if a site forces me to change my password?+

Increase the version number for that site and generate a new one. Write down the version you use for each site: it isn’t secret.

Is it safe to use on a website?+

All the work happens in your browser with the Web Crypto API: neither the master key nor the passwords ever leave your device.
